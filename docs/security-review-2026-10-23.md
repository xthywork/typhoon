# 安全與邏輯檢查紀錄（2026-10-23）

檢查涵蓋本地 HTTP 服務、資料快取與排程、官方來源解析、歷史匯入、前端更新與分享狀態，以及隨專案提供的地圖函式庫。以下是本次確認並修正的問題。

| 範圍 | 問題 | 修正 |
| --- | --- | --- |
| 私人檔案 | 公開路徑的符號連結可指向專案內 `.env`；缺少 index 時會產生目錄列表 | 固定資產白名單、GET／HEAD 共用驗證、拒絕符號連結與目錄列表 |
| HTTP 資源 | 無快取時每個請求等待 85 秒；慢連線沒有處理數上限 | 冷啟動立即回覆 503／Retry-After、15 秒 I/O 期限、64 個處理工作上限 |
| 跨網站請求 | 外站可發出訪客更新請求 | 檢查 Fetch Metadata 與 Origin，拒絕跨網站 API 請求 |
| HTML 顯示 | 地圖提示使用 HTML 字串；缺少腳本來源限制 | 動態提示改用文字節點、前端腳本抽離、同源 CSP、禁止嵌入框架 |
| 相依套件 | MapLibre 5.6.2 受 GHSA-jrc7-96c5-q579 影響 | 升級官方 6.11.2，核對 npm tarball SHA-512，保留來源與檔案 SHA-256 |
| 資料交易 | 來源逐筆提交後，整輪發布失敗可能留下部分新資料 | 整輪狀態、產品及完成時間在單一交易內提交，失敗回滾 |
| 產品時效 | 成功下載舊產品會重新標成最新活動資料 | 驗證每個系統最新發布／分析時間；拒絕異常未來時間，舊 CMA 批次仍可保存 |
| 氣旋識別 | 無編號 JMA 低壓可能共用 ID；跨年可能拆成兩個系統 | 使用唯一 TC code、官方季年及受限的跨年延續規則 |
| CWA 解析 | 要求每小時更新的分析與較早預報起算時間相同，拒絕有效產品 | 預報使用原始起算時間與對應分析點，完整保留更新較快的分析及風圈 |
| HKO 解析 | 後一個系統缺少分析點時沿用前一個基準時間 | 每個氣旋重設基準並要求有效分析 |
| 時間解析 | 無時區時間受主機時區影響；1958–1968 被解成 2058–2068 | 拒絕缺少時區的即時時間；歷史年份依指定年度解析 |
| 歷史匯入 | 空檔／部分成功可能覆蓋完整資料；合法跨年路徑被拒絕 | 拒絕空檔及覆蓋範圍縮減、整年原子替換、依官方季年接受跨年邊界 |
| 前端更新 | 回應覆蓋等待期間的新選擇、選單索引變動選錯颱風、空資料殘留舊詳情 | 收到回應才讀當前選擇、使用穩定 ID、資料清空時清除詳情；以原始發布／有效時間保留已選預報詳情 |
| 分享與時區 | 分享歷史游標被同步狀態覆蓋、尚未進入快取的分享目標遺失、時區文字過期 | 保存同步模式／兩軌／游標、延後還原分享目標、時區切換重算更新文字 |
| 分析來源 | 中央位置使用 CWA，但歷史線／提示可能使用 JMA | 中心、歷史線、時間軸、預報相對時間與提示共用同一分析序列 |

MapLibre 問題與修補版本依據[維護者安全公告](https://github.com/maplibre/maplibre-gl-js/security/advisories/GHSA-jrc7-96c5-q579)。本地使用固定底圖與固定 attribution，未發現既有頁面會接收外部 attribution 的操作入口；仍更新套件並加入該漏洞的屬性移除回歸檢查。

## 驗證

- `python3 -m unittest discover -s tests -v`：25 個測試，使用離線 fixture、暫存 SQLite 與本地 HTTP。
- `node tests/frontend.cjs`：19 個檢查，使用真實 Leaflet／MapLibre 與本地壓縮底圖；所有氣象請求均攔截成測試資料。

- Python 編譯、JavaScript 語法與 Git 空白檢查；未把授權碼或快取加入 Git。
