# 官方氣象資料串接

## 現階段範圍

本機 `server.py` 只有在有人請求 `/api/typhoons`，且快取超過一小時或尚無快取時，才擷取各機構官方公開產品，透過 `/api/typhoons` 提供統一格式。資料格式為網站用 JSON／JSONP、公開 XML 或官方網頁產品，**不代表每個來源都有穩定的對外 API 契約**。上游格式改變時顯示解析失敗，不會補入模擬資料。

| 來源 | 已實作 | 目前限制 |
| --- | --- | --- |
| CWA | 會員正式 API `W-C0034-005` XML；未設定金鑰時使用官方網站產品 | 金鑰只由伺服器讀取；使用 XML 的 `Sent` 與各點原始時間，保留分析歷史與預報。設定金鑰後若授權失敗，不會默默退回網頁來源。 |
| JMA | `targetTc.json`、`specifications.json` | 網站公開 JSON；歷史分析從本機開始擷取後累積，不推算無時間戳的繪圖座標。 |
| HKO | 官方熱帶氣旋清單及 `hko_tctrack_*.xml` | 只匯入有明確時間的分析／預報點；略過僅供畫線、沒有時間的中間節點。 |
| CMA | 中央氣象台官方台風網 JSONP | 匯入 BABJ 預報與過去實況／批次；不把其他機構資料冒充 CMA。 |
| KMA | 來源與待設定狀態 | 正式介面需要帳號、認證與資料欄位驗證；此版尚未實作認證 adapter。 |
| JTWC | 官方主機連線檢查與失敗狀態 | 此環境無法解析官方主機；ATCF 路徑介面尚未驗證，沒有以別家的路徑替代。 |

CWA 正式 API 已實作。KMA 仍等待帳號、認證及正式介面驗證。

## 時間與資料語意

- 同季、同英文命名的氣旋合併；無名低壓保留來源識別，避免錯配。
- 位置時間軸採單一機構的官方分析序列，CWA 正式 API 有完整歷史時優先使用，否則保留最多已知分析點的來源；來源顯示於地圖左上角。各機構的中心定位可能不同。
- 地圖中心標記、風圈、摘要採同一來源同一筆資料的時間與座標；預設優先 CWA，聚焦其他來源時三者一起切換。
- 分析位置的可選時間不得超過該來源所選預報批次的初始分析時間，避免舊批次風圈疊到新位置。
- 啟用七級／十級風圈時，若該來源有對應半徑，位置滑桿只使用相關風圈與位置共同有資料的官方時刻；風速低於該風圈門檻的紀錄仍可查看。官方未提供的整個風圈類型維持未提供，不為了提高頻率補算或沿用另一時間的半徑。
- 多個已啟用且有提供資料的風圈類型完全沒有共同完整時刻時，停用位置滑桿與播放並隱藏分析中心，顯示無共同資料；關閉限制圖層後再恢復有效時刻。
- 點選未來預報點會讓中心與風圈一起顯示該預報點，標記清楚顯示「來源、預報、有效時間」。拖曳／播放分析位置時間軸會離開預報點預覽，恢復同時刻的分析位置與風圈。
- 兩條滑桿共用**實際時間**尺度，分別停在真實分析時刻與發布／產品更新時刻，不再假設固定六小時或固定五個批次。
- 批次滑桿是「截至此時」：每個來源顯示該時刻以前最新的已儲存預報，實際發布／更新時間見左側。上游沒有提供、且本機還未儲存的歷史批次不會被產生。
- 初次啟動，CMA 公開產品含過去預報批次；CWA 正式 API 包含過去分析位置，但只包含當下預報批次；其餘預報批次之後才逐次累積。SQLite 以來源、氣旋、發布／產品更新時間去重。
- 預報點保留來源的有效時刻，不假設每十二小時一點。缺少風速、氣壓、陣風或機率半徑時保留 `null`。
- 風速統一為 m/s，但保留各來源的平均時間，沒有進行平均時間換算。
- CWA 的 15 m/s 七級風圈與 25 m/s 十級風圈分開顯示，不當成精確的 30 kt 風圈。四象限完整時依官方 NE／SE／SW／NW 半徑畫四個圓弧區段；不完整時只使用官方平均半徑，沒有半徑就不畫。
- 右上角顯示目前來源、分析時間、最大風速、陣風、氣壓、官方移動速度與風圈平均半徑。歷史位置滑桿改變時，使用該分析時刻的資料；點選預報點時，風圈與機率圈改為該預報點資料，詳情顯示於原有面板。
- 官方中心位置 70% 機率圈與暴風圈分開標示。預設顯示目前來源的各預報機率圈；選取預報點時只保留該點的圈。這不是暴風影響範圍，也不是自行推估的警戒區。
- 七級風、十級風與中心位置機率圈可在右側圖層設定獨立切換。其他來源只有 30 kt 半徑時才使用該圖層，缺值不換算／補造。
- 上游暫時失敗時保留上次成功的產品並標示狀態；快取擷取時間超過 48 小時後不再當成活動系統顯示。成功回覆無活動氣旋會清空該來源活動清單。

## 申請 CWA 授權碼

1. 開啟 [氣象資料開放平臺](https://opendata.cwa.gov.tw/)。
2. 點會員登入／註冊，依指示用有效電子郵件完成會員註冊及驗證。
3. 登入後開啟 [API 授權碼](https://opendata.cwa.gov.tw/user/authkey)，取得會員授權碼。
4. 確認可取得「颱風消息與警報－熱帶氣旋路徑」產品 `W-C0034-005`。各資料集支援的格式以網站為準。
5. 將授權碼填入專案 `.env` 的 `CWA_API_KEY`，或設定同名環境變數（環境變數優先），不需要貼到對話或加入 Git。可參照 `.env.example`，取得授權碼後由伺服器下載正式 XML。

[CWA 官方開發指南](https://opendata.cwa.gov.tw/devManual/description) 說明註冊僅需有效郵件、會員授權碼與下載參數；正式檔案介面使用 `Authorization` 參數。

## 申請 KMA API Hub 認證

1. 開啟 [KMA API Hub](https://apihub.kma.go.kr/)，選會員註冊（회원가입）。
2. 完成帳號及聯絡方式驗證；官方目前要求手機聯絡驗證。海外門號是否可用請以申請頁的實際選項為準，無法完成時可先保留其他四個來源。
3. 進入 [颱風資料](https://apihub.kma.go.kr/apiList.do?seqApi=8)，針對「태풍정보」選「API 활용신청」，依指示申請資料使用。
4. 取得 `authKey` 後先存放本機。需另行實作並驗證正式 adapter，不會在前端或日誌中公開金鑰。

[KMA 使用介紹](https://apihub.kma.go.kr/apiInfo.do) 與各介面的申請條件以官方頁面為準。

## CWA 本機設定

在專案根目錄 `.env` 填寫：

```dotenv
CWA_API_KEY=你的CWA授權碼
```

此檔案已加入 `.gitignore`，HTTP 服務也不提供隱藏檔案。金鑰由後端讀取，帶金鑰的 URL 透過 curl 標準輸入傳送，不放在命令列參數、前端、來源連結或資料快取內。正式資料介面依據 [CWA 熱帶氣旋產品規格](https://www.cwa.gov.tw/Data/data_catalog/1-4-1.pdf) 解析。

程式更新後需重啟資料服務；之後修改金鑰會在下一次符合一小時更新條件的資料請求時讀取。

## 執行與快取

```sh
python3 server.py --bind 0.0.0.0 --port 8000
```

需要 Python 3.10+ 及 `curl`。標準函式庫實作，沒有額外 pip 套件。伺服器同時提供地圖靜態檔案與 `/api/typhoons`；原本的 `python3 -m http.server` 只能供應靜態檔案，不能提供此 API。

- 每個上游請求有連線與總時間限制，六個來源並行處理。
- 沒有背景擷取排程，服務啟動時也不擷取。網頁開啟或按重新整理時才請求資料；頁面不會定時自動讀取。
- 上一輪擷取完成後一小時內共用快取；過期後由下一個資料請求觸發整輪擷取。同時請求只進行一輪，其餘等待共用結果。
- 一小時是依本機完成擷取的時間計算，與氣象機構產品發布時間無關。失敗來源仍保留原有成功時間與錯誤狀態，不會因為後續訪客而立刻重試，下一輪仍需等一小時。
- 一小時的完成時間儲存在 SQLite；重啟服務仍可使用尚未過期的快取，不會為重啟而再次下載。
- `.cache/weather.sqlite3` 保存來源狀態與預報批次；不加入 Git。請保留此檔才能保留本機逐次累積的批次。
- HTTP 僅公開前端資產與固定 API，不公開 Python 原始碼、隱藏目錄或快取資料庫。
- 尚無快取或快取已過期時，第一個資料請求需等待官方資料下載；即使其中來源失敗，也可顯示其他成功來源。
