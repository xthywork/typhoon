# 官方氣象資料串接

## 現階段範圍

本機 `server.py` 依台灣時間（UTC+8）每小時 05、20、25、50 分背景擷取各機構官方公開產品，無論有無訪客或活動氣旋，透過 `/api/typhoons` 提供統一格式。資料格式為網站用 JSON／JSONP、公開 XML 或官方網頁產品，**不代表每個來源都有穩定的對外 API 契約**。上游格式改變時顯示解析失敗，不會補入模擬資料。

| 來源 | 已實作 | 目前限制 |
| --- | --- | --- |
| CWA | 會員正式 API `W-C0034-005` XML；未設定金鑰時使用官方網站產品 | 金鑰只由伺服器讀取；使用 XML 的 `Sent` 與各點原始時間，保留分析歷史與預報。設定金鑰後若授權失敗，不會默默退回網頁來源。 |
| JMA | `targetTc.json`、`specifications.json` | 網站公開 JSON；歷史分析從本機開始擷取後累積，不推算無時間戳的繪圖座標。 |
| HKO | 官方熱帶氣旋清單及 `hko_tctrack_*.xml` | 只匯入有明確時間的分析／預報點；略過僅供畫線、沒有時間的中間節點。 |
| CMA | 中央氣象台官方台風網 JSONP | 匯入 BABJ 預報與過去實況／批次；不把其他機構資料冒充 CMA。 |
| KMA | 來源與待設定狀態 | 正式介面需要帳號、認證與資料欄位驗證；此版尚未實作認證 adapter。 |
| JTWC | NOAA/NWS 官方轉送的 JTWC `ABPW10 PGTW` 概況與 `WTPN31～35 PGTW` 座標警報 | 目前支援西北太平洋；不需帳號。依概況的活動系統與引用頻道讀取最新 JTWC 原文，不依賴本環境無法解析的 Navy 主機。 |

CWA 正式 API 已實作。KMA 仍等待帳號、認證及正式介面驗證。

### JTWC 資料來源與解析

- 概況來源為 `https://tgftp.nws.noaa.gov/data/raw/ab/abpw10.pgtw..txt`；從西北太平洋的活動氣旋摘要讀取 `WTPN31～35 PGTW` 引用，再下載相應的 `https://tgftp.nws.noaa.gov/data/raw/wt/wtpn32.pgtw..txt` 等警報。
- NOAA/NWS 為官方轉送管道，警報發布者仍為 JTWC（PGTW），`url` 與 `transport=noaa-nws-jtwc-bulletin` 保留實際出處。沒有使用 NOAA 或其他機構的預報取代 JTWC。
- 發布時間取 WMO 警報表頭，以內文年月日定位；分析時間取 `WARNING POSITION`，預報時間必須同時符合 `VALID AT` 與真實時效，處理月底／跨年。不以 `REMARKS` 內發布時刻外推位置取代分析位置。
- 風速與陣風從節轉為 m/s，維持一分鐘平均的資料語意；分析氣壓只取明確對應分析時刻的數值，預報未提供氣壓維持 null。
- 保存 34／50／64 kt 的 NE／SE／SW／NW 四象限半徑，海里轉公里；不當成 CWA 15／25 m/s 風圈，也不冒稱 30 kt。現有畫面以 CWA 分析風圈為主，JTWC 象限資料先隨預報點保留。
- 最終警報不列為活動系統；概況超過有效期 12 小時或警報發布已超過 18 小時，回報來源過期，由既有後端失敗回退機制處理。概況無法解析或有活動系統卻缺少引用時回報錯誤，不當成「沒有颱風」。
- 2026-10-23 實際取得 CHAMPI（29W）第 033 報，發布時間 2026-10-22 15:00 UTC，分析時間 12:00 UTC；含分析點及 12、24、36、48、60、72、96 小時預報點。未批次匯入歷史警報；後續批次由原有排程逐次保存。

## 時間與資料語意

- 同季、同英文命名的氣旋合併；跨年優先使用官方季年。無名低壓保留來源與原始編號，JMA 缺少正式編號時使用唯一 TC code，避免錯配。
- 位置時間軸、中央標記、歷史線、七級／十級風圈與右上摘要優先使用 CWA 分析序列，不受來源勾選、聚焦或預報點選取影響。缺少 CWA 時使用後端選定的實際分析來源，並標明提供商。使用不晚於位置游標的最新分析；無資料時顯示提示，不插值或補算半徑。預報詳情顯示於摘要下方。
- 兩條滑桿共用**實際時間**尺度，分別停在真實分析時刻與發布／產品更新時刻，不再假設固定六小時或固定五個批次。
- 批次滑桿是「截至此時」：每個來源顯示該時刻以前最新的已儲存預報，實際發布／更新時間見左側。上游沒有提供、且本機還未儲存的歷史批次不會被產生。
- 初次啟動，CMA 公開產品含過去預報批次；CWA 正式 API 包含過去分析位置，但只包含當下預報批次；其餘預報批次之後才逐次累積。SQLite 以來源、氣旋、發布／產品更新時間去重。
- CWA 每小時分析可能比現有預報起算時間更新；分析歷史完整保留，預報 `base` 及起點則使用原始 `InitialTime` 和相應官方分析，不將最新分析冒充舊預報起點。
- 預報點保留來源的有效時刻，不假設每十二小時一點。缺少風速、氣壓、陣風或機率半徑時保留 `null`。
- 風速統一為 m/s，但保留各來源的平均時間，沒有進行平均時間換算。
- CWA 的 15 m/s 七級風圈與 25 m/s 十級風圈分開顯示，不當成精確的 30 kt 風圈。四象限完整時依官方 NE／SE／SW／NW 半徑畫四個圓弧區段；不完整時只使用官方平均半徑，沒有半徑就不畫。
- 右上角顯示目前分析來源的時間、風速、陣風、氣壓、移動速度與風圈平均半徑；取消所有來源仍顯示。
- CWA 官方中心位置機率圈與暴風圈分開標示；預報機率圈仍隨 CWA 預報圖層顯示與選點，不改變分析風圈。
- 七級風、十級風與中心位置機率圈可在右側圖層設定獨立切換。其他來源只有 30 kt 半徑時才使用該圖層，缺值不換算／補造。
- 上游暫時失敗時保留上次成功的產品並標示狀態；快取擷取時間超過 48 小時後不再當成活動系統顯示。成功回覆無活動氣旋會清空該來源活動清單。

## 申請 CWA 授權碼

1. 開啟 [氣象資料開放平臺](https://opendata.cwa.gov.tw/)。
2. 點會員登入／註冊，依指示用有效電子郵件完成會員註冊及驗證。
3. 登入後開啟 [API 授權碼](https://opendata.cwa.gov.tw/user/authkey)，取得會員授權碼。
4. 確認可取得「颱風消息與警報－熱帶氣旋路徑」產品 `W-C0034-005`。各資料集支援的格式以網站為準。
5. 將授權碼填入專案 `.env` 的 `CWA_API_KEY`，或設定同名環境變數（環境變數優先），不需要貼到對話或加入 Git。可參照 `.env.example`，取得授權碼後由伺服器下載正式 XML。

[CWA 官方開發指南](https://opendata.cwa.gov.tw/devManual/description) 說明註冊僅需有效郵件、會員授權碼與下載參數；正式檔案介面使用 `Authorization` 參數。

## 申請 KMA API Hub 認證

1. 開啟 [KMA API Hub](https://apihub.kma.go.kr/)，選會員註冊（회원가입）。
2. 完成帳號及聯絡方式驗證；官方目前要求手機聯絡驗證。海外門號是否可用請以申請頁的實際選項為準，無法完成時可先保留其他四個來源。
3. 進入 [颱風資料](https://apihub.kma.go.kr/apiList.do?seqApi=8)，針對「태풍정보」選「API 활용신청」，依指示申請資料使用。
4. 取得 `authKey` 後先存放本機。需另行實作並驗證正式 adapter，不會在前端或日誌中公開金鑰。

[KMA 使用介紹](https://apihub.kma.go.kr/apiInfo.do) 與各介面的申請條件以官方頁面為準。

## CWA 本機設定

在專案根目錄 `.env` 填寫：

```dotenv
CWA_API_KEY=你的CWA授權碼
```

此檔案已加入 `.gitignore`，HTTP 服務也不提供隱藏檔案。金鑰由後端讀取，帶金鑰的 URL 透過 curl 標準輸入傳送，不放在命令列參數、前端、來源連結或資料快取內。正式資料介面依據 [CWA 熱帶氣旋產品規格](https://www.cwa.gov.tw/Data/data_catalog/1-4-1.pdf) 解析。

程式更新後需重啟資料服務；之後修改金鑰會在下一輪背景擷取時讀取。

## 執行與快取

```sh
python3 server.py --bind 0.0.0.0 --port 8000
```

需要 Python 3.10+ 及 `curl`。標準函式庫實作，沒有額外 pip 套件。伺服器同時提供地圖靜態檔案與 `/api/typhoons`；原本的 `python3 -m http.server` 只能供應靜態檔案，不能提供此 API。

- 每個上游請求有連線與總時間限制，六個來源並行處理。
- 服務啟動後等待下一個指定時間，依台灣時間每小時 05、20、25、50 分開始一輪；無訪客、無颱風或來源失敗時仍持續排程。
- 固定排程之外，開啟網站或手動重新整理時請求 `/api/typhoons?visit=1`。距離上輪完成超過 5 分鐘（或無快照）才啟動背景擷取，立即提供既有快照；多人同時訪問共用同一輪。排程與訪客觸發的抓取以同一把鎖串行執行；等待期間已有新一輪完成時，直接共用該結果。
- 一般 `/api/typhoons` 版本檢查不觸發抓取。前端開啟後每秒檢查一次，共 10 次，此後每 3 分鐘一次；離開頁面會清除計時器，從瀏覽器快取返回頁面則重啟檢查。
- 後端以資料內容（包含來源狀態與路徑，但不包含單純擷取時間）產生 SHA-256 `version` 和 ETag。客戶端送出 `If-None-Match`，無變動回覆 304，不下載完整資料、不更動 DOM、不重畫地圖。背景檢查失敗時保留畫面。
- 有變動才套用新快照，保留選取的颱風、來源、地圖視角及歷史時間位置；原本停在最新資料時跟隨最新時間。
- 每輪來源請求並行進行；全輪由同一把鎖保護，不會重疊。若一輪跨過下一個排程時間，略過錯過的排程，不立即補抓多輪。
- 失敗來源保留原有成功時間與錯誤狀態，下一輪仍在排程時間執行。最新活動產品若已超過 48 小時或時間異常，視為來源失敗；JTWC 另有較嚴格的期限。整輪資料與完成時間在單一 SQLite 交易中提交，意外失敗會回滾，也不會停止後續排程。
- 完成時間與批次持續儲存在 SQLite；重啟可先供應既有快照，並等待下一個指定時間擷取。
- 僅固定排程約每日 96 次 CWA 授權下載；若有訪客觸發的擷取，會另計次數。一般每秒／每 3 分鐘的版本檢查不消耗 CWA 額度。
- `.cache/weather.sqlite3` 保存來源狀態與預報批次；不加入 Git。請保留此檔才能保留本機逐次累積的批次。
- HTTP 使用固定資產白名單，GET／HEAD 同樣拒絕符號連結與目錄列表；僅公開前端與固定 API。連線有 15 秒 I/O 期限與 64 個處理工作上限，並限制跨網站 API 請求。前端腳本獨立成檔，搭配同源 CSP。
- 完全沒有快照時立即回覆 503 與 `Retry-After: 1`，不佔用連線等待整輪抓取；頁面顯示資料準備中並自動檢查。

## 單次匯入 2026 年歷史颱風

```sh
python3 import_history.py --year 2026
```

這是手動執行的單次作業，不會由 HTTP 請求或定時器執行。匯入完成後重啟 `server.py`，歷史颱風即可出現在原有搜尋選單。

- 以 CWA 歷史資料庫公開的年度名單限定範圍，保留中文名稱與 CWA 原始編號。2026-10-22 查得 29 個颱風。
- 跨平台以同年度英文名稱核對，保留各平台原始編號；不直接用不同平台的編號配對。例如 CWA CHAMPI 為 202629，CMA 為 2630。
- CMA 匯入這 29 個颱風的歷史分析位置及有明確發布時間的預報批次。沒有發布時間的舊產品只保留分析位置，不以分析時間冒充發布時間。
- JMA 依年度最佳路徑檔補入資料，目前檔案有 2601～2608 共 8 個颱風。最佳路徑屬於事後分析，沒有歷史預報批次；此匯入目前取用其位置、氣壓與風速欄位。
- CWA 公開歷史頁面可查名單及路徑圖，逐點下載另有研究用帳號限制；既有 Open Data API 授權碼不會用來冒充資料庫登入。此次沒有匯入 CWA 歷史逐點資料。
- 中央分析位置與摘要優先使用已取得的 CWA 資料；缺少 CWA 時，使用後端選定的歷史分析來源，畫面會顯示實際提供商。未提供的風圈與陣風欄位維持「未提供」。
- SQLite 的 `archive_imports` 保存 CWA 名單與匯入報告，`archive_storms` 保存各提供商資料；既有即時 `bulletins` 與背景擷取排程不受匯入影響。歷史資料不因即時來源停止列出颱風而消失。
- 匯入報告另存 `.cache/history-2026-manifest.json`，資料庫及報告都不加入 Git。重複執行會更新指定年度的歷史快照。
- 若任一來源擷取失敗、空檔、無法配對或覆蓋範圍縮減，整次匯入不覆寫既有年度。兩位數年份依指定季年解析，允許合理的相鄰年邊界，避免重試時遺失歷史。
- HKO、KMA、JTWC 的歷史檔案尚未接入；不以其他平台資料填入這些來源。
